# SO-101 · OMX-AI 리더암 → Isaac Sim 1차 구성

확인된 범위: PC의 Isaac Sim 5.1에서 종류별 가상 Follower 한 대를 함께 띄우고,
각 종류의 실물 Leader를 독립 입력으로 사용한다. 장비는 OMX-AI 기본 조립과
손목 카메라가 달린 SO-101이다. 실제 Follower 구동·공정·학습은 이번 단계 밖이다.

- SO-101: TheRobotStudio 카메라 포함 new-calibration URDF.
- OMX: ROBOTIS `omx_f.urdf`; OMX-L은 입력 장치다.
- ROS 2 Jazzy, domain 42 기본. `/so101/joint_command`, `/omx/joint_command` 입력;
  모델별 `/joint_states` 피드백. 입력과 시뮬레이터 프로세스 분리.
- 모델별 전체 관절 이름·라디안·범위 확인 후 속도 제한을 거쳐 물리 드라이브에 전달.
- OMX 두 손가락은 반대 부호 명령으로 동기화한다. 원본 URDF는 보존한다.
- 실제 모터 입력은 SDK 읽기 전용. EEPROM/토크/목표 위치를 변경하지 않는다.
  별도 시뮬레이션 기준 자세 등록으로 하드웨어 영점 가정을 피한다.
- 수신 단절 0.5초 후 가상 팔의 현재 위치를 유지한다. 시뮬레이션용 제어이며
  실물 안전제어기로 재사용하지 않는다.
- 손목 카메라 메시는 URDF에서 유지한다. 가상 렌더 카메라는 추가하며 광학 보정은
  실물 측정 전 근사값이다.
- Raspberry Pi 5로 이전할 대상은 ROS 2 입력/실물 I/O. Isaac Sim은 GPU PC에 유지.

검증: URDF 메시/관절 검증 → 헤드리스 두 모델 물리 동작 → ROS 2 가상 입력과
실제 관절 응답 → 입력 단절 → 렌더 화면 → 실물 연결 후 관절별 방향·그리퍼.
실물 미연결이면 마지막 항목은 미검증으로 명시한다.

## 검증 중 확정한 내부 설정

Isaac Sim 5.1의 ROS2PublishJointState가 이 환경의 GPU PhysX 텐서를 CPU 버퍼로
요청해 실패하므로 두 팔 1차 테스트의 물리 장치는 CPU로 고정한다. 렌더링은 RTX GPU를 사용한다.
기본 PD 이득은 stiffness 150, damping 4이며 실물 모터 동역학을 재현한 수치는 아니다.
카메라 형상은 +Z 방향으로 26.3 mm까지 연장되어 있어 가상 광학 원점을 28 mm에 둔다.
실제 카메라 내부 파라미터와 정확한 광학 중심은 별도 측정 대상이다.

2026-09-10 사용자 확인: 재료 3종별 4칸 용기 3개. 두 분리된 나무 작업대,
준비 용기 1세트, 조립 지그, 완성품 저장 1칸. OMX 준비 이송과 SO-101 조립을
리더 직접 모드로 시연하고 두 팔의 동기 관절 기록을 별도 재생 모드에서 사용한다.
학습 정책은 아직 데이터가 없어 구현 대상이 아니며, 기존 단독 로봇 시험 명령은 유지한다.
