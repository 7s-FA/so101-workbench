# SO-101 실시간 전압 모니터

실행:

```bash
final
./scripts/voltage.sh
```

브라우저에서 <http://127.0.0.1:8765>를 연다. 종료는 실행 터미널에서 Ctrl+C.
동작 중인 서버가 있으면 새로 실행하지 않고 주소만 연다.

- 모터 1~6번을 목표 60Hz로 읽는다. 실제 주기는 화면에 표시한다.
- 현재·누적 최저·최고 전압, 온도, 보호 하한, 오류 표본 수와 통신 오류 수를 표시한다.
- 모터에서 읽은 전압은 0.1V 단위다. 외부 계측기의 측정값이 아니다.
- 30/60/120초 그래프는 0.1초 구간별 최저·최고값을 표시하여 한 표본의 순간 저전압도 보존한다.
- 연속된 모터 오류는 한 사건으로 묶고 최근 30개 사건을 표시한다. 화면의 오류 표본 수는 매 측정마다 누적된다.
- 연결이 끊기면 전압을 0V로 만들지 않고 `응답 없음`으로 표시한다. USB 재연결은 자동 재시도하며,
  USB를 그대로 둔 전원 재연결은 다음 읽기에서 감지한다. 전원 없이 시작했으면 연결 후 보호 하한도 다시 읽는다.
- `화면 일시정지`는 표시만 정지한다. 측정·CSV 기록은 계속된다.
- 모든 표본은 `outputs/voltage/so101_날짜_시간.csv`에 저장된다. `CSV 내려받기`는 현재까지 기록한 파일을 내려받는다.
- 통신에 실패한 행은 전압 칸을 비워 둔다. `communication_result`가 0인 행에서만 센서값을 해석한다.
- 오류가 발생해도 진단 기록을 계속한다. 팔을 움직이는 명령이나 모터 설정 변경은 하지 않는다.

SO-101 포트는 모니터가 단독 사용한다. SO-101 `io.sh` 입력 프로그램은 먼저 종료해야 하며,
모니터 실행 중에는 같은 장치를 다른 프로그램에서 열 수 없다. OMX는 다른 포트이므로 함께 사용 가능하다.

다른 장치 경로/표시 포트가 필요한 경우:

```bash
./scripts/voltage.sh --port /dev/serial/by-id/실제장치경로 --http-port 8766
```

서버는 이 PC의 localhost에만 열리며 외부 CDN·네트워크 연결 없이 작동한다.
기록은 종료할 때까지 계속 쌓인다. 초기화하려면 서버를 종료한 뒤 다시 실행하며 기존 CSV는 보존된다.

검증: 순간 저전압 보존, 연속 오류 사건 집계, 통신 실패의 결측 처리, 오래된 값 표시,
상태 비트 없는 임계값 위반에 대한 단위 시험을 추가했다.

## 전압 모니터 + SO-101 자동 복구 연동

```bash
final
./scripts/voltage.sh --teleop
```

이 모드에서는 별도 SO-101 `io.sh`를 실행하지 않는다. 한 프로세스가 모터 위치·전압·오류를
같이 읽고, 정상 위치값만 `/so101/joint_command`에 발행한다. OMX 입력은 기존대로 실행한다.

- 통신 실패, 모터 오류, 전압 한계 이탈, 관절 매핑 범위 이탈 시 입력을 중단하고
  `/so101/input_hold`에 정지 요청을 보낸다. 시뮬레이터는 다음 처리 시점에 현재 관절 위치를 목표로 유지한다.
- 모터 6개가 모두 정상이고 관절 매핑도 정상인 응답이 연속 3회 수신되면 추종을 재개한다.
  60Hz에서 약 50ms의 확인 구간이며 실제 시간은 읽기와 시뮬레이터 처리 속도에 따라 달라진다.
- 재개 시 관절 목표는 기존 3rad/s 제한을 거쳐 움직인다. 가상 팔의 물리적 정지에는 관성·접촉 영향이 있다.
- 프로세스가 사라지거나 정지 신호도 전달되지 않을 때는 기존 0.5초 입력 타임아웃이 적용된다.
- 화면 상단에 추종/가상 팔 유지 상태, 원인과 자동 복구 횟수를 표시한다.
- 오류는 CSV에 계속 기록한다. 실물의 저전압 보호 설정과 토크는 변경하지 않는다.
- 모터 전원이 실제로 끊긴 동안 위치값을 얻는 기능이 아니다. 정상 통신 복귀 후 재개하는 기능이다.
- 모니터만 필요한 경우 `--teleop` 없이 실행한다. 기존 `io.sh`는 오류 시 종료하는 동작을 유지한다.

`input_hold`는 std_msgs/Float64이며 양수는 정지 요청의 Unix 시간, 0은 해제다.
시뮬레이터는 0.5초 이내의 새 요청만 사용한다. 기존 demo와 replay 모드는 이 외부 신호를 무시한다.
USB 재연결 후에도 보정 기준이 유지되어야 하며, 관절이 허용 범위를 벗어나면 기준 자세 쪽으로 옮겨야 한다.

검증: 단위 시험 24개 통과. 실물 저전압(그리퍼 3.8/3.9V) 발생 중 모니터가 유지되고,
시뮬레이터 HOLD→TRACKING 전환을 확인했다. 관절 범위 이탈 중 명령 발행이 멈추고 정지 요청과
가상 관절 피드백은 계속되는 것도 확인했다. 근거: `outputs/live_recovery_sim.log`,
`outputs/live_recovery_monitor.log`, 해당 실행의 전압 CSV.

### 관절 한계 처리 변경

리더가 관절 한계를 벗어나면 해당 가상 관절만 한계 위치로 제한하고 나머지 관절은 계속 추종합니다. 리더가 범위 안으로 돌아오면 해당 관절도 다시 움직입니다. 화면에 `한계 유지` 관절명을 표시합니다. 전압·통신 오류 표본은 여전히 전체 보류 및 정상 3회 확인 대상입니다.
