# Sim_real — 최신 실물 구성의 공정 시연

`final` 실행 후 다음 명령을 사용합니다.

```bash
final
./Sim_real/start.sh
```

브라우저에서 **http://127.0.0.1:8767/** 을 열고 **시연 시작**을 누릅니다. Isaac Sim GUI 없이 웹으로 확인합니다. 종료는 실행한 터미널에서 `Ctrl+C`입니다. 중복 실행은 잠금으로 차단합니다.

터미널에는 준비·완료 안내와 오류를 표시하고 반복 경고는 숨깁니다. 경고를 포함한 원본 출력은 `Sim_real/outputs/sim_real_demo/terminal.log`에 실행마다 새로 기록합니다. 경고를 터미널에서도 보려면 `./Sim_real/start.sh --show-warnings`를 사용합니다. 경고의 표시만 바꾸며 원인을 해결하거나 오류를 무시하는 설정은 아닙니다.

## 공정

- A/C: SO-101 + XLeRobot 그리퍼 + 측면 D435. B/D: OMX. C는 공식 상부 카메라 연결 받침의 7.2mm 상승량을 반영합니다.
- 3×2m 맵, 400×400mm 재료대, 900×400mm 조립대. 컨베이어와 B/D의 추가 밑판은 없습니다.
- 운반로봇 1에 재료 9개, 재료대에 9개로 시작합니다. 총 18개를 처리해 완제품 6개를 만듭니다.
- 뚜껑은 결합면이 아래로 향하도록 처음부터 공급합니다. 네 구멍은 향후 자석 체결용이며, 현재 시연은 결합 위치에서 보조 고정합니다. 자력·유지력은 모델링하거나 검증하지 않았습니다.
- A는 재료를 하나 옮길 때마다 대기 자세를 거치지 않고, 간섭을 확인한 경로로 다음 재료에 접근합니다. 9개 상차를 마치면 안전 자세로 복귀합니다.
- B는 한 세트 3개를 연속 하차한 뒤 빈손으로 안전 자세에 복귀하고 C의 조립 동안 그 자세를 유지합니다. C는 연속 조립 후 D에게 인계하고 복귀합니다. D는 별도 낮은 받침대의 용기에 직접 적재한 뒤 복귀합니다.
- B/C, C/D는 공유 공간을 순차 사용하고, B/D와 A는 허용된 구간에서 동시에 작업합니다. 팔의 복귀와 차량 도착은 시뮬레이터 위치 응답으로 확인합니다.
- 빈 용기 2개는 처음에 창고 상단에 있습니다. 첫 운반로봇 도착 뒤 지게차가 빈 용기를 가져와 받침대에 내려놓고 물러납니다. 완제품 3개가 담기면 회수해 창고에 보관합니다.
- 운반로봇과 지게차는 모두 전방을 향해 도킹합니다. 모든 차량은 도킹 위치에서 통로(y=-0.42m)까지 방향을 유지한 채 직선 후진하고, 통로에서 도킹 위치까지는 직선 전진합니다. 운반로봇의 차체 방향을 바꾸면서 적재판의 지그 방향도 조정해 기존 부품 집기 위치를 유지합니다.
- 이동은 직선 구간만 사용합니다. 차량은 완전히 멈춘 뒤 제자리에서 90° 회전하며, 이동 중 회전과 출발 직후 180° 회전은 사용하지 않습니다. 회전 속도 상한은 0.55rad/s(약 32°/초), 각가속도 상한은 0.40rad/s²입니다. 제자리 회전의 시작과 끝은 5차 보간으로 완만하게 연결합니다. 지게차는 가로 통로에서 항상 왼쪽을 바라봅니다. 창고 방향으로는 전진하고 작업대 방향으로는 후진하며, 통로 끝에서 정지·방향 정렬 후 전진 도킹합니다. 포크·용기를 포함해 실제 사용한 회전 방향의 간섭을 검사합니다.
- 두 번째 재료 운반을 첫 배치의 창고 보관보다 먼저 진행해, B·C가 다음 배치를 작업하는 동안 지게차가 창고 보관과 빈 용기 회수를 수행합니다. 도로는 한 차량씩 사용하며 D는 빈 용기 배치 완료 응답을 기다립니다.
- 인접 창고 사이도 통로까지 후진한 뒤 이동합니다. 빈 포크는 다음 회수에 쓸 삽입 높이를 유지해 반복 승강을 줄이고, 최종 보관이 끝나면 최저 높이로 내립니다. 운반로봇 1은 기존 대기 구역에, 운반로봇 2는 재료 상차 위치에 주차합니다. 2번은 마지막 세트 하차 후 C·D의 조립·출하와 병행해 복귀합니다. 주차 목표는 적재판 중심과 바닥 네모가 일치하도록 차체 원점의 32mm 오프셋과 방향을 반영합니다.
- 지게차는 창고 1 앞의 전용 대기 위치(-0.39m, 0.305m, 위쪽 방향)에서 시작하고, 최종 보관 후 포크를 내린 채 같은 위치로 복귀합니다. 통로 사용권은 주차 완료 후 해제하며 주차를 마쳐야 전체 작업이 완료됩니다.
- 모든 팔의 안전자세는 베이스 위로 무게중심을 모으는 세운 자세입니다. A·C는 방향을 가지런히 맞췄고, 그리퍼 중심의 수평 돌출은 베이스에서 약 22~28mm입니다. 정지 중력 부하는 URDF 질량·무게중심으로 비교하며, SO-101 카메라·마운트 추가 질량 0/100/150g 가정도 확인합니다. 실제 질량·전류·온도 측정에 의한 보증은 아닙니다. 결과는 `rest_check.json`에 기록합니다.
- 시작·일시정지·재시작·배속 선택, 전체 영상과 팔 카메라 4개를 제공합니다. SO-101은 깊이 영상, OMX는 공용 상부 영상으로 전환합니다. 영상 갱신 목표는 최대 15fps이며 실제 속도는 PC 성능에 따라 달라집니다. 전압·부하 진단 창은 없습니다.
- 차량 상태 카드에서 전진·후진·제자리 회전, 도킹·대기, 적재량과 지게차 포크 높이를 확인합니다. 전체 작업 순서는 A~D 팔과 차량의 30개 작업을 시작 시간순으로 표시하며, 각 작업을 펼치면 집기·놓기·이동·승강·용기 처리 단계를 볼 수 있습니다. 완료 표시는 팔 안전 복귀와 차량 도착 응답을 반영합니다.
- 전체 탑뷰·사선뷰는 기존 해상도(렌더링 1200×800, 웹 전송 960×640)를 유지하고 JPEG 품질을 92로 높였습니다. 색상 축소도 사용하지 않아 압축 손실을 줄입니다. 팔 카메라는 기존 설정을 유지합니다.

## 용기 받침과 지게차 치수

| 항목 | 설정 |
|---|---:|
| 완제품 용기 바닥 | 208×72×3mm, 기존 9mm 완제품 지그 3개 연결(빈 용기 총높이 12mm) |
| 창고 외곽 | 각각 268×125mm, 용기 1개 폭 |
| 1·2층 판 두께 | 모두 5mm |
| 1층 윗면 / 판 아래 여유 | 20mm / 15mm |
| 상단 선반 / 작업대 용기 받침 높이 | 95mm |
| 층간 간격 | 75mm |
| 포크 | 길이 140mm, 폭 22mm, 두께 3mm 가정 |
| 포크 최저 윗면 / 아래쪽 지면 여유 | 4mm / 1mm |
| 리니어 스트로크 | 최대 100mm, 현재 공정 사용량 최대 96mm |
| 선반의 포크 통로 | 폭 36mm, 포크 양옆 7mm씩 |

두 선반과 받침대는 뒤쪽 가로대에 연결된 삼지창 형태입니다. 하단 용기 진입 때 앞 기둥에 걸리지 않도록 폭을 잡았습니다. 완제품이 담긴 용기를 하단에서 5mm 들었을 때 위 선반 아래에는 약 25.4mm가 남습니다.

**포크는 용기보다 5mm 낮게 진입합니다.** 1층 진입 시 포크 윗면은 15mm이며, 하단 용기를 들어 올릴 때는 25mm입니다. 포크 두께·실제 최저 높이·바닥 평탄도·도킹 오차를 실측해야 합니다. 3mm 포크의 강도, 실제 리니어의 하중 정격과 유효 스트로크는 확인되지 않았습니다. 치수상 100mm 리니어를 사용할 수 있다는 결과이며 실물 적재 성공 보장은 아닙니다. 실제 포크의 최저 높이가 하단 선반보다 높다면, 리니어 스트로크만 늘려서는 하단 진입 문제가 해결되지 않으며 포크 장착 높이도 바꿔야 합니다.

## 검증과 한계

현재 공정 기준 시간은 배속 없이 약 **588초(9분 48초)**입니다. 회전 제한을 완만하게 유지하고 불필요한 경로·승강·대기를 줄여 10분 이내로 조정했습니다. PC 성능이나 실물 도킹·인식 재시도에 따른 실제 소요 시간은 별도이며 실물 작업 시간은 아직 측정하지 않았습니다.

| 팔 동작 | 관절 속도 상한(rad/s) | 관절 가속도 상한(rad/s²) |
|---|---:|---:|
| 빈손 이동 | 2.24 | 5.0176 |
| 부품 운반 | 1.68 | 3.136 |
| 정밀 접근 | 0.952 | 2.5088 |
| 그리퍼 | 0.896 | 2.25792 |

차량의 직선 속도 상한은 0.225m/s, 평면 가속도 상한은 0.128m/s²입니다. 통로까지의 후진과 가로 통로에서의 지게차 방향을 검증합니다. 이동과 회전은 분리하며 각 구간 경계에서 정지하는지 확인합니다. 비교와 세트 완료 후 안전 자세 검사는 `motion_quality_check.json`, 도킹 방향과 실제 회전 범위는 `docking_check.json`에 기록합니다. 토크·발열·하중 및 실제 바닥 마찰에 의한 슬립 검증은 포함하지 않습니다.

최신 결과는 `outputs/sim_real_demo/verification.json`과 그 파일이 참조하는 보고서에 있습니다. 모델과 경로가 바뀌면 이전 합격 결과로 실행하지 않습니다. 다시 검사하려면:

```bash
final
./Sim_real/scripts/verify_real_demo.sh
```

검사는 유한한 시간 안에 종료하며 서버를 남기지 않습니다. 실제 Isaac Sim 재생 이미지와 USD는 `outputs/sim_real_demo/verified/`에 생성합니다.

현재 시연은 정해진 경로·집기 보조 고정·볼 낙하 위치 보조를 사용합니다. 형상 검사는 실제 메시의 표본 검사이며 연속 충돌의 수학적 보장, PLA 마찰에 의한 파지, 접촉력·스냅 결합·학습 정책·Nav2·실물 로봇 제어를 검증한 결과는 아닙니다. 집기와 놓기 끝점은 수직 자세를 사용하고, 직선·원호 보간 구간에서는 5축 팔의 도달 제약 때문에 최대 3도 방향 오차를 허용합니다. A의 수평 운반과 대기 복귀는 관절 경로를 사용합니다.

`arm_sim/real_demo.py`가 공정 배치와 동작 설정의 원본입니다. `config/conveyor_demo.json`은 이전 배치 설명을 포함한 자산 목록이며 현재 공정의 높이·좌표는 `real_layout()`에서 정합니다. `Demo` 폴더의 이전 시연은 독립적으로 유지합니다.
