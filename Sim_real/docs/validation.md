# 2026-09-10 · 수행한 검증

환경: Ubuntu 24.04, ROS 2 Jazzy, Isaac Sim 5.1.0, RTX 4070 SUPER 12GB.
두 팔 물리 계산은 CPU, 렌더링은 GPU. 실제 리더/팔로워는 연결하지 않았다.

## 통과

- SO-101 손목 카메라 포함 URDF와 OMX-F URDF의 메시 파일 경로·관절 구조 확인.
- 같은 장면에 두 모델을 변환·배치하고 모든 관절을 물리 드라이브로 구동.
- 단위 테스트 7개: 이름 순서 재배열, 누락·중복·NaN·범위 초과 거부,
  입력 단절 유지, 원시 위치 래핑, OMX 손가락 반대 방향, 그리퍼 역방향 범위 처리.
- 3,600 물리 스텝의 모델별 순차 관절 테스트. 전 관절·그리퍼 약 0.35~0.36 rad 변화 확인.
  최대 명령 추종 오차: SO-101 약 0.0116 rad, OMX 약 0.0474 rad.
  이 값은 현재 시험 궤적과 가상 PD 구동기의 결과이며 실물 정밀도 평가가 아니다.
- 외부 ROS 2 퍼블리셔가 모델마다 958개 메시지 송신, 시뮬레이터가 모델마다 956개 수락.
  최신 메시지를 사용하는 queue 1 구성으로 전체 메시지 전달을 보장하는 시험이 아니다.
- 외부 노드가 실제 관절 feedback을 SO-101 2,812개, OMX 2,813개 수신.
  모든 관절에서 움직임 확인. 로그: `outputs/check_ros_final.log`.
- 입력 중단 후 양쪽 모두 `HOLD (input timeout)` 진입.
  로그와 보고서: `outputs/sim_final.log`, `outputs/validation_report.json`.
- 전체 보기 및 손목 카메라 렌더 이미지를 생성하고 화면을 확인.

## 아직 확인하지 못한 것

- 실제 리더의 포트·모터 상태·기준 자세·관절 방향과 지연.
- 실제 팔로워 구동 및 정밀도, 실물 카메라 intrinsics/extrinsics.
- Raspberry Pi 5에서의 실행·네트워크 지연.
- 물체 집기·접촉·자체 충돌·공정 통합·학습.

## 구현에서 반영한 차이

OMX는 기존 OpenMANIPULATOR-X가 아니라 `omx_f` 모델이다.
원본의 그리퍼 mimic은 생성본에서 제거하고 두 손가락에 반대 목표각을 전달한다.
가상 그리퍼 범위는 +/-1.1 rad로 제한했다. SO-101은 new calibration 모델이므로
기존 보정값을 자동 추정하지 않고 시뮬레이션용 기준 자세를 별도 저장한다.
카메라 영상 방향은 USD 광학 축에 맞춰 변환했다. 광학 파라미터는 실물 보정 전 근사값이다.

최종 카메라·종료 확인: `outputs/final_smoke.log`, 300 스텝 실행 종료 코드 0.
설치된 Isaac Lab의 STOP 콜백이 렌더 루프를 유지하므로 종료 시에만 해당 핸들러를
비활성화한다. 이 처리는 이 PC의 설치 버전에 맞춘 것으로 Isaac Lab 업데이트 시 재검증한다.
초기 렌더 stage-id 및 형상이 없는 프레임 링크의 visual 참조 경고는 로그에 남아 있지만,
두 로봇 형상과 카메라 렌더, 관절 상태 수신을 별도로 확인했다.
