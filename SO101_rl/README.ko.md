## 실행

앱 목록 또는 바탕화면의 **완제품 B 시뮬** 아이콘을 실행하면 Isaac Sim 창이 열린다. 장면 준비가 끝나면 B 에피소드를 **자동 재생**한다. 오른쪽 패널의 **일시정지 / 재생 / 처음으로**로 조작한다. 처음으로는 초기 배치로 돌아가 정지하며, 재생으로 다시 시작한다. 에피소드가 끝나면 결과를 표시하고 멈춘다. 종료는 창의 닫기 버튼을 사용한다. 실물 장비에는 연결하지 않는다.

기본 화면은 **등록된 상단 카메라에서 보는 시점**이다. 로봇팔2 프로필의 `base_from_camera` 위치·방향, 1280×720 해상도, 내부행렬 K와 렌즈 왜곡 D를 Isaac의 OpenCV 렌즈 모델에 적용한다. 임의의 수직 탑뷰가 아니다. 카메라 외부 좌표는 현재 저장된 CAD 추정값이며 실측 검증값은 아니다. 마우스로 시점을 바꾼 뒤 **상단 카메라 시점** 버튼을 누르면 등록된 시점으로 돌아간다. 적용한 좌표·광학 설정은 `top_camera.json`에 기록한다. 광학 원점 안쪽의 20mm 표시용 렌즈가 시야를 가리지 않도록 근거리 클리핑은 30mm로 두며 카메라 위치와 장면의 충돌 형상은 옮기지 않는다.

아이콘 실행 기록은 `outputs/viewer_날짜_시간/launch.log`, 재생 결과는 같은 폴더의 `viewer_result.json`에 저장된다. 중복 실행은 막으며, 실행 오류는 메시지로 표시한다. 터미널에서는 `bash SO101_rl/launch_viewer.sh`로 같은 화면을 연다. 대화형 `--mode view`만 창을 표시하고, 아래의 학습·자동 평가 명령은 headless로 실행된다.

### 시뮬 지그 위치로 티칭 적용

기본 위치는 B 에피소드에 저장된 운반 지그 기준이다. 오른쪽 **운반 지그 위치 · 로봇팔2 기준**에서 X(mm), Y(mm), 방향(°)을 바꾼 뒤 **지그 위치 적용 · 경로 재계산**을 누른다. 터틀봇·운반판·지그와 B 부품을 함께 옮기고, 같은 위치를 최신 OpenCV `corrected_plan`에 넣어 다시 계산한다. 계산이 끝나면 초기 자세에서 정지하며 **재생**으로 시작한다.

지그를 따라가는 12개 스텝만 보정하며, 고정된 놓기 위치·안전 자세·집게 틱은 유지한다. 이전 보정 결과에 다시 보정을 누적하지 않고 항상 원래 티칭을 기준으로 계산한다. 현재 OpenCV 방식과 동일하게 높이와 기울기는 고정하고 XY와 방향을 지원한다.

Isaac 편집 기능으로 옮길 때는 개별 메시 대신 **`/World/Carrier` 전체 그룹**을 선택한다. **장면 위치로 계산**은 그 그룹의 실제 좌표를 읽는다. 재생 중 그룹 위치가 바뀌면 즉시 일시정지하며, 재생 버튼을 누르면 현재 장면 좌표로 재계산 후 처음부터 실행한다. **저장 위치 복원**은 에피소드의 원래 지그 위치로 돌아간다. 잘못된 좌표나 도달 불가능한 경로는 적용하지 않고 이전 유효한 장면·경로를 유지한다.

시뮬에서의 변경은 원본 티칭/카메라 보정 파일을 바꾸지 않으며 현재 실행에만 적용된다. 적용한 좌표와 계산 오차는 `jig_application.json`, 갱신한 경로는 `resolved_plan.json`에 남긴다. 영상 검출 대신 시뮬 장면 좌표를 입력으로 사용하는 방식이다. 자동 시험의 시작 위치도 `--jig-pose X_MM Y_MM YAW_DEG`로 지정할 수 있다.

위치 변경 검증: X +2mm, Y +1mm, 방향 +0.5°에서 지그 연결 스텝 12개가 갱신되고 최대 TCP 위치 잔차는 약 0.30mm였다. 회귀 검사 11개와 숨긴 Isaac 창에서 위치 적용·장면 편집 감지·재계산·저장 위치 복원을 확인했다. 이 수치는 경로 계산 잔차이며 실물 정확도나 파지 성공률이 아니다.

### OpenCV 티칭의 에피소드 실행 조건

현재 `SO101_teach/so101_teach/motion.py`의 **`MotionSession.on_snapshot` 실행 코드를 직접 사용**한다. 별도 시뮬 전용 도착 판정을 복제하지 않는다. 이 코드만 독립 모듈로 읽어 시계를 시뮬 시간으로 바꾸고, 모터 읽기·쓰기는 메모리 버스로 연결한다. 시리얼 연결·작업자 스레드·실물 토크 활성화는 실행하지 않는다.

- 로봇팔2 프로필의 집게 접촉 부하를 그대로 읽는다. 현재 기준은 **raw 70**이다.
- 닫는 명령을 보낸 상태에서 부하가 기준 이상이고 위치 변화가 **3틱 이내**, **0.12초·3회 이상** 지속되어야 접촉으로 확정한다. 움직이는 중의 순간 부하, 기준 아래로 내려간 부하, 오래 끊긴 피드백은 접촉으로 확정하지 않는다.
- 확인 중에는 이미 보낸 닫기 목표보다 더 닫지 않는다. 접촉이 확인되면 현재 위치를 유지 목표로 기록하고 이후 운반에도 유지한다. 8틱을 넘는 열기 명령에서 유지 조건을 해제한다.
- 몸체 ±20틱·집게 ±30틱 안에서 **0.2초 도착 확인**을 거친다. 접촉 후보가 남아 있으면 다음 단계로 넘어가지 않는다. 연속 통과점, 어깨·팔꿈치 부하 오차 보정, 에피소드의 작은 잔여 오차 허용, 5초 도착 지연 처리도 원본 실행 코드가 담당한다.
- 학습 보정은 도착 대기 중의 자세나 확인 중/유지 중의 집게 목표를 우회하지 못한다. 운반 단계가 되었다는 이유로 집게 토크 한도를 별도로 낮추던 시뮬 처리는 제거했다.

**부하 판정 코드와 기준값은 같지만 N·m 환산은 아직 실측 보정되지 않았다.** 집게 raw 추정은 같은 로봇팔2 보정을 사용하는 실물 세션 **14개·1,194개 샘플**의 정지 상태 위치 오차/부하 관계를 사용한다. 실제 위치와 서보 내부 목표의 차이가 14틱인 기록의 중앙값은 raw 68, 15틱은 raw 80으로 현재 접촉 기준 70의 양쪽을 포함한다. 오차별 중앙값을 단조 보정해 보간하며, 기록 범위인 0~39틱 밖에서는 끝값을 유지하고 범위 초과 횟수를 결과에 남긴다. 이 범위 밖에서 실제 부하가 검증되었다는 뜻은 아니다. 모델과 원본 로그 SHA는 `config/gripper_load_model.json`에 있고 `fit_gripper_load.py`로 재생성한다.

집게 raw 추정은 **원본 에피소드에서 집게 목표 틱을 줄이는 닫기 스텝에만** 적용한다. 열기·현재 벌림 유지·접근 스텝에서 부품에 밀려 벌어진 위치 오차를 닫기 부하로 만들어 전달하지 않는다. 이 제한은 실물 센서 규칙을 바꾼 것이 아니라, 정지 상태 닫기 기록으로 만든 시뮬 추정 모델의 사용 범위를 제한한 것이다. 원본 `GripperContact`와 접촉 해제 조건은 수정하지 않는다.

몸체 5관절은 같은 보정의 실물 세션 **16개·관절 샘플 33,769개**로 만든 `config/arm_load_model.json`을 사용한다. 정지에 가까운 속도(5틱/초 이하)이고 관절별 기록 오차 범위 안일 때만 오차/부하 중앙값을 보간한다. 기록 밖의 오차나 움직이는 상태는 기존 토크 비율 추정으로 돌아가며, 범위 초과 횟수를 관절별로 기록한다. 위치 피드백을 먼저 정수로 반올림한 뒤 속도를 구하던 방식을 고쳐, 4틱/초 같은 작은 속도가 0 또는 10틱/초로 바뀌지 않게 했다.

이 모델은 정지 상태의 부하 근사이며 동적 서보 응답이나 접촉력을 측정한 모델이 아니다. 서보 P/D 계수와 시뮬 강성·감쇠의 실측 대응도 없어, 같은 실행 조건을 사용한다는 것과 실물과 같은 힘·파지 결과가 검증되었다는 것을 구분해야 한다. 화면에는 **집게 티칭 목표 / 실제 틱**, **부하 추정 / 기준 raw · 실측 기록 기반 · 토크 환산 미보정**을 표시한다.

집게 구동은 `config/servo_response.json`에서 기존 실험용 강성 2·토크 상한 0.15N·m를 강성 20·상한 0.6N·m로 조정했다. 기존 손목과 같은 토크 상한을 사용하는 시뮬 추종 조정이며 실물 모터 토크를 측정한 값은 아니다. 동일한 접근에서 집게 벌림 오차는 약 99틱에서 15틱으로 줄었지만, 부품 접촉과 팔 관절의 도착 실패는 남았다. 몸체 설정·원본 에피소드 틱·부하 접촉 기준·도착 허용치는 바꾸지 않았다.

`result.json`과 `viewer_result.json`의 `gripper_contacts`는 접촉 확인 부하·시간·샘플 수·유지 틱, `step_arrivals`는 원본 실행기가 기록한 도착 목표·실제 틱·오차·부하 보정을 담는다. `elapsed_physics_s`는 대기를 포함한 물리 시간이며 `time_s`는 원래 경로에 대응시킨 진행도다. 실행기와 부하 모델이 바뀌었으므로 이전 학습 정책은 그대로 재사용하지 않는다.

프로젝트 루트에서 실행한다. 기존 `/path/to/isaac/env_isaaclab/bin/python`을 사용하며, 별도 설치는 필요하지 않다. 다른 설치 경로는 `SO101_RL_PYTHON` 환경변수로 지정한다. 출력은 기본적으로 실행별 새 폴더에 저장된다.

현재 UI에서 로봇팔3가 선택되어 있어도 이 시험은 B 에피소드에 연결된 **로봇팔2**를 선택한다. 같은 지그라도 부품별 티칭 기준이 다르므로, 첫 스텝의 저장 지그 위치를 명목 장면에 두고 최신 보정 계산으로 후속 스텝을 맞춘다. 원래 스텝은 `reference_episode.json`, 계산 결과는 `resolved_plan.json`에 따로 남긴다.

최신 로봇 메시·관절·메시 배치가 Test_teach 물성 모델과 일치할 때만 관성을 옮긴다. 일치하지 않으면 실패하며 오래된 모델로 자동 대체하지 않는다. 지그의 180° 메시 방향과 현재 표시 배치를 원본으로 사용하고, 위의 명시적 시뮬 보정을 별도로 적용한다. 배치가 CAD/카메라 추정이라는 기존 한계도 유지된다.

기준 물성은 패드 정지/운동 마찰 **1.0/0.8**, 주변 표면 마찰 **0.5**, 반발 **0**, 팔 토크 한도 **2 N·m**, 손목 **0.6 N·m**, 집게 기본값 **0.15 N·m**이며 현재는 `servo_response.json`에서 **0.6 N·m**로 덮어쓴다. 이전 설정의 운반 **0.08 N·m** 전환은 사용하지 않으며, 티칭 실행기가 접촉 시점의 위치 목표를 유지한다. 이는 기존 시뮬 설정이며 실물 서보 토크 보정값이 아니다. Sim_real의 오래된 A 부품 질량과 마찰 0.8은 비교 자료로만 보관한다. 보조 고정·충돌 해제·매 프레임 물체 위치 갱신은 학습에 사용하지 않는다.

상단은 사용자가 확인한 대로 **운반용 지그에서 처음부터 뒤집힌 상태**로 시작한다. 원본 STL은 보존하고 180° 회전 후 접촉 높이를 다시 계산한다. 상단의 안착 높이는 지그 자체 좌표에서 약 15.55mm이며, 바로 놓았을 때보다 3.2mm 낮다. 상·하단은 주황색, 중단은 파란색이다. 운반 지그 아래에는 현재 OpenCV 설정의 터틀봇 버거와 195mm 지지대를 재사용한다. 터틀봇은 주차된 고정 배치이며 주행 제어는 없다.

상단은 원본 삼각형 메시 검사에서 초기 간섭이 없었지만 convex decomposition 물리 실행에서는 기울거나 튀는 문제가 있었다. 홈의 충돌 근사 오차를 의심해 정밀도를 높였으나 남아, **GPU PhysX의 SDF 충돌, 해상도 512**로 바꿨고 초기 안착이 안정화됐다. 하우징에도 같은 SDF를 적용하여 TPU가 들어갈 내부 공간을 보존한다. SDF 선택 근거는 [NVIDIA의 충돌 형상 문서](https://nvidia-omniverse.github.io/PhysX/physx/5.2.1/docs/RigidBodyCollision.html#dynamic-triangle-meshes-with-sdfs)에 설명되어 있다.

표면은 최신 OpenCV의 로봇·집게 색, 흰 PLA와 작업대, 금속 표현, `grey-stone-tiles.png` 바닥 텍스처를 재사용한다. 텍스처의 반복과 바닥 좌표도 유지하며, 렌더러 색 공간 차이를 보정한다. 조명은 넓은 천장 광원 두 개와 실내 간접광으로 근사한 **5000K 형광등 환경**이다. 사용자 요청으로 천장 광원 강도를 12,000→18,000(1.5배), 간접광을 250→600(2.4배)으로 높였다. 실제 조도·광원 위치를 측정한 값은 아니다.

사용자가 B의 실측 무게가 없다고 확인했으므로, 하단/상단은 기존 PLA 출력 추정 질량과 메시 체적의 비율, 중단은 기존 TPU 집게의 압출량 추정 질량과 메시 체적의 비율로 초기 질량을 추정한다. 이 방법은 B의 인필·벽 두께를 재슬라이싱한 결과가 아니다. 초기 추정값은 하단 약 **11.7g**, 중단 약 **17.3g**, 상단 약 **11.8g**이며, 실제 실행값과 출처는 `source_manifest.json`에서 확인한다.

## 학습과 평가 의미

- 관측: 실제 읽기/추정 가능한 관절각·관절속도, 티칭 기준 관절각, 이전 행동, 경로 진행도. 물체의 시뮬 정답 좌표는 정책 입력에 넣지 않는다.
- 행동: 6개 관절 목표 보정. 몸체 관절 ±2°, 집게 ±3°로 제한하고 CAD/모터 관절 범위와 목표 변화율을 적용한다. 원래 32스텝 순서는 유지한다.
- 시간: 기존 물리 간격 1/480초, 정책 제어 30Hz. 한 GPU 물리 환경과 CPU PPO를 사용하며 대규모 병렬 학습은 포함하지 않는다.
- 변화 조건: 에피소드별 질량/관성 배율 0.8~1.2, 명시적으로 연결된 부품·패드·TPU 집게 접촉 재료의 마찰 배율 0.8~1.2, 구동 이득 배율 0.85~1.15, 명령 지연 0~2 제어 주기, 부품 초기 XY ±1mm, 관절각 잡음 표준편차 0.1°. 모두 시험용 범위이며 실물 식별 결과가 아니다. 현재 성공 판정은 명목 조건에만 해당한다.
- 보상: 관절 추종·작은 보정·행동 연속성, 부품 들어 올림과 목표 접근/놓기. 물체의 물리 좌표는 보상과 평가에만 쓴다.
- 성공: 세 부품이 각 집기 구간에 30mm 이상 올라 0.25초 이상 유지된 이력이 있어야 한다. 하우징이 리니어 팔레트에 안착한 뒤 TPU가 내부에 삽입되어야 하며, 캡은 TPU 높이에 따른 간격을 유지하면서 네 자석 쌍이 모두 작용해야 한다. 집게를 놓고 전체 경로를 끝낸 뒤 이 조립 상태를 0.5초 유지해야 한다. 부품 속도는 0.02m/s 미만이어야 한다.
- 실패: 큰 관절 추종 이탈, 작업대 아래로 낙하. 잘못된 수치·원본/보정 불일치는 실행 오류로 중단한다.

놓기 목표는 실제 B CAD의 팔레트 안착·하우징 내부 TPU 안착·캡 접촉 높이로 계산한다. 하우징 XY 오차 2mm, TPU와 캡의 상대 XY 오차 1.5mm 등 자세·높이 조건은 `config/assembly.json`에 있다. 중단 TPU와 집게 패드는 강체이며 탄성 변형은 계산하지 않는다. 자석 힘과 질량은 임시 모델이므로 시뮬 결과를 실물 성공률로 해석하지 않는다. 아래 과거 시험 기록의 집기·놓기 판정은 당시 기준이며 현재 조립 판정과 다르다.

### CAD 정합과 B 조립 구조

`config/cad_alignment.json`의 이동·방향·기울기는 운반판과 부품의 고정 배치를 보정한다. 카메라에서 관찰한 지그 이동과 구별하며 원본 티칭 목표를 다시 쓰지 않는다. `--cad-offset DX DY DZ`, `--cad-yaw DEG`, `--cad-tilt ROLL PITCH`로 실행별 후보를 시험한다. 이동은 축별 ±30mm, 방향 ±12°, 기울기 ±4° 범위다. `nest_offsets_mm`를 사용하면 지정한 B 받침과 해당 부품을 함께 옮긴다. 이 보정은 시뮬 후보이며 실측 정합값이 아니다. 리니어 전체 배치는 `config/assembly.json`의 `receiver_offset_mm` 또는 `--receiver-offset DX DY DZ`로 보정한다.

리니어 충돌 제외 코드가 `ear` 문자열을 검사하여 `linear`까지 제외하던 오류를 고쳤다. 지금은 팔레트·레일·캐리지에 실제 충돌이 있다. 하우징을 팔레트에 먼저 놓고 TPU를 그 안에 삽입한 뒤 캡을 올리는 순서로 판정한다.

CAD에서 얻은 네 구멍은 지름 약 **6.3mm**, 깊이 **2.2mm**다. 각 구멍에 같은 크기의 자석을 표시하고 추정 질량을 포함한다. 서로 마주 보는 자석 쌍 사이에 최대 **0.12N**, 거리 **6mm** 이내에서만 작용하는 인력을 적용한다. 힘과 토크는 두 부품에 반대로 적용하며 순간 이동이나 고정 조인트를 사용하지 않는다. 힘·밀도는 사용자가 허용한 임시값이며 실측 자석 사양은 아니다.

TPU와 캡의 CAD 접촉 높이로 계산한 캡·하우징 간격은 **1.6mm**다. 캡을 하우징에 완전히 밀착시키지 않는다. `outputs/assembly_component_check/result.json`의 별도 물리 검사에서는 간격 약 **1.50mm**, 네 자석 쌍, 하우징 안착과 TPU 내부 배치를 유지했다. 이 검사는 조립 근처에 놓인 부품의 안정성 검사로, 로봇의 전체 조립 성공을 뜻하지 않는다.

단단한 접촉만 사용하면 접촉 시점의 현재 집게 각도로 유지 목표를 바꾼 뒤 압력이 풀리는 경우가 관찰됐다. 패드와 TPU 집게 몸체에는 선택적으로 [PhysX의 탄성 접촉](https://docs.omniverse.nvidia.com/kit/docs/omni_physics/latest/dev_guide/rigid_bodies_articulations/rigid_bodies.html)을 적용할 수 있다. 이는 접촉의 스프링·감쇠 근사이며 메시 전체의 탄성 변형 해석이 아니다. 계수는 실측값이 아니며 `servo_response.json`의 `pad_contact`와 `assembly.json`의 `tpu_contact`에서 적용 여부를 확인한다. 원본 티칭 실행기의 유지 각도·raw 70 기준은 그대로 사용한다.

평가는 학습과 다른 seed를 사용하고, 보정 없는 경로와 학습 정책에 동일한 seed와 조건을 적용한다. 명목/변화 조건을 나눠 결과를 남긴다. 짧은 학습은 실행 점검 목적이므로 성능 향상을 보장하지 않는다.

## 출력

- `source_manifest.json`: 원본 코드·보정·형상 SHA와 적용/비교 물성, 제한.
- `scene.json`, `reference_episode.json`, `resolved_plan.json`: 사용 장면과 티칭 기준.
- `scene.usda`, `assets/`: Isaac Sim 장면과 로봇 USD/메시.
- `scene.png`: `--capture` 사용 시 초기 장면 실제 렌더링.
- `step_*.png`, `checkpoints_*.json`: `replay --capture`의 주요 스텝 실제 렌더링과 관절별 오차·물체 자세 기록.
- `policy.zip`, `policy_contract.json`: PPO 정책과 입력·원본 계약. 실물 배포 파일이 아니다.
- `train_monitor.csv`, `result.json`: 학습 에피소드와 명목/변화 조건의 기준선·정책 평가.
- `error.json`: 시뮬 실행 오류. 원인 기록 전에 성공으로 처리하지 않는다.

`run.sh`는 Isaac Sim 종료가 예외 코드를 가리는 경우를 막기 위해 결과 저장 후 완료 표시를 별도로 확인한다. 소스/보정/물성/속도가 바뀐 정책은 그대로 재평가하지 않는다. 현재 환경은 실물 연결·정책 업로드 기능을 제공하지 않는다.

### 지그 수정 후 화면 자세가 남는 문제

숨긴 화면을 실제 물리 링크 좌표와 대조하면서, 지그 이동·복원 뒤에 GPU 물리 관절은 움직여도 렌더링된 로봇이 이전 자세에 남는 현상을 확인했다. 숫자만 확인하던 화면 동작 검사로는 이 문제를 잡지 못했다. 단순 일시정지만으로는 재현되지 않았고, 화면용 관절 재초기화나 물리 장면 재시작만으로도 해결되지 않았다.

`render_pose.py`는 현재 물리 링크와 부품의 **실제 위치·방향**으로 표시 메시를 매 프레임 갱신한다. 표시 메시에는 물리 API를 제거하며 원래 충돌체·질량·관절 상태는 유지한다. 티칭 목표를 실제 자세처럼 그리거나 부품을 집게에 붙이는 처리가 아니다. 뷰어와 이미지 캡처가 같은 표시 경로를 사용하고, 카메라 렌더링도 뷰어 시작 시 활성화한다.

지그를 옮겼다가 저장 위치로 복원하고 하단 접근까지 실행한 뒤 정지한 실제 화면에서 수정 결과를 확인했다. `outputs/viewer_jig_render_check/viewer_ui.png`가 최종 화면이고 `viewer_render_state.json`에 같은 시점의 관절·TCP·부품 위치가 있다. 이때 집게 목표는 2450틱, 실제는 2466틱이며 TCP는 로봇팔2 기준 약 **[184.13, -167.43, 15.83]mm**였다. 원래 상단 카메라 좌표와 조명은 유지한다. 이 렌더링 수정은 앞서 기록한 물리 도착 실패를 해결했다는 의미는 아니다.
