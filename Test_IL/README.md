# SO-101 모방 학습

교체 그리퍼를 장착한 SO-101 리더·팔로워의 시연 기록, 로컬 ACT 학습, 기록 및 모델 실행 프로그램입니다. 기본 렌더러는 OpenCV 티칭과 같은 MuJoCo/OpenGL 방식으로 실제 관절값을 표시합니다.

## 실행

```bash
final
cd Test_IL
./start.sh
```

기본 실행은 전용 창, 로컬 서버, 가벼운 자세 렌더러를 함께 엽니다. Isaac Sim은 실행하지 않습니다. 팔은 자동으로 연결하거나 움직이지 않습니다. 웹으로만 열려면 `./start.sh --web`을 사용합니다. 주소는 `http://127.0.0.1:8768/`입니다. 종료 시 해당 실행에서 제어한 팔의 힘을 해제합니다.

## 현재 장비 기준 · 2026-09-22

- 팔로워: `OpenCV_teach/follower.json`에 등록된 오른쪽 SO-101, STS3215 ID 1~6.
- 보정: `OpenCV_teach/calibration/opencv_follower_right/follower_right.json`을 그대로 읽습니다. 실행이나 파일 등록 과정에서 모터 영점·범위 보정을 덮어쓰지 않습니다.
- 리더: SO-101. **모터 영점 조절 → 리더암 → USB → 보정 파일 선택**에서 등록하거나 새로 보정합니다. 모터와 파일의 보정값을 연결 때 대조하며 팔로워 보정을 리더에 복사하지 않습니다.
- 그리퍼: 최신 `Test_teach`의 XLeRobot 홀더·파란 TPU 손가락·얇은 패드.
- 그리퍼 카메라: 32×32 UVC 모듈. 상단 카메라: RealSense D435. 장치 연결에서 그리퍼는 UVC, 상단은 **RealSense D435 · 컬러·깊이 · 일련번호**를 선택합니다.
- 학습 입력: 그리퍼 UVC RGB + 상단 D435 RGB, 640×480, 30Hz. D435의 깊이도 함께 저장·재생하지만 ACT 입력은 RGB 2대 그대로입니다.
- 시뮬: 최신 `Test_teach/config/so101_scene.json`의 작업대와 SO-101 모델. 기본 자세는 앱 시작 때 `config/robot.json`의 `default_pose_program`에 지정한 OpenCV 티칭 에피소드의 시작·종료 안전자세와 당시 모델 보정을 함께 읽습니다. 화면 기본 각도는 저장된 관절값에 해당 에피소드의 모델 보정을 더한 값입니다. OpenCV에서 안전자세를 갱신하면 다음 실행에 반영됩니다. 실물 연결 후에는 공식 모터 보정으로 읽은 실제 관절값을 그대로 표시합니다. 연결만으로 안전자세로 이동하지 않습니다. 부품·지그 없이 팔 자세만 표시합니다. 공식 32×32 상단 마운트의 아래·중간 부품과 받침을 사용하고, 맨 위 부품을 D435용으로 바꿨습니다. 팔 밑에는 해당 받침의 실제 모델 높이 5mm가 추가됩니다. 그리퍼는 XLeRobot 원본 손목 카메라·마운트 모델입니다. 상단 D435는 기둥에서 앞으로 돌출됩니다. 카메라 외부 보정·구멍 위치·강도는 실측 검증 전입니다.

## 기록과 확인

1. 장치 연결에서 팔과 카메라를 선택합니다. 연결만으로 모터 힘이 켜지지 않습니다.
2. 새 SO-101 작업 폴더를 만듭니다. 기존 OMX 작업 폴더에는 SO-101 기록을 섞지 않습니다.
3. 리더 따라가기로 현재 팔로워 자세에서 리더 자세에 맞춘 뒤 조작합니다.
4. `R`로 녹화를 시작·종료하고 `S`로 저장합니다. 저장 후에도 팔 조작은 유지됩니다. `Shift+R`은 현재 녹화만 버립니다.
5. 기록 확인에서 개별 결과·학습 사용 여부·삭제를 관리하고 원본 시간대로 영상과 시뮬을 봅니다. 같은 로봇·보정의 기록만 실물 재실행할 수 있습니다.

`F8`은 동작을 멈추고 힘을 유지합니다. 모터 힘 끄기는 팔을 받친 뒤 사용합니다. Ctrl+C 또는 전용 창 닫기로 종료할 때도 SO-101 프로토콜로 힘을 해제하고 확인합니다. 종료가 지연되면 이 실행의 자식 프로세스만 정리한 후 별도 해제를 시도합니다.

녹화 중 카메라가 끊기면 상단에 알리고 녹화를 중단합니다. 불완전한 녹화는 정상 학습 기록으로 저장하지 않습니다. 팔 조작과 카메라 복구는 별개입니다.

## 학습·모델 실행

ACT·ResNet18 및 LeRobot의 저장·학습·추론 코드를 사용합니다. 학습 횟수, batch, 학습률, 예측 길이, 다음 예측 전 실행 길이 등을 설정할 수 있습니다. 학습 중 새 기록 수집, 저장된 체크포인트에서 이어 학습, 최신 모델만 보관하는 옵션을 유지합니다. 새 기록은 현재 학습 데이터에 실시간으로 삽입하지 않고 다음 이어 학습 때 반영합니다.

원본에는 관절 라디안, 실제 관측·제한 전 리더 목표·실제로 전달한 명령, 프레임 및 취득 시간을 저장합니다. LeRobot 변환은 **몸체 5관절=도, 그리퍼=0~100**이며 최신 OpenCV 티칭의 `use_degrees=True`와 같습니다. 기존 OMX의 −100~100 몸체 값을 SO-101에 재사용하지 않습니다. ACT 내부 정규화는 저장된 학습 통계를 사용합니다.

모델 실행은 모델 선택·준비 후 실물에서 실행합니다. 원본 방식은 모델의 목표를 직접 전달하며, 비동기 추론·블렌딩·필터는 선택 옵션입니다. 목표는 팔로워 보정 범위로 제한합니다. 시작 자세 이동은 본 에피소드와 구분합니다. 시뮬 접촉으로 실물을 중단하지 않습니다.

## 공식 모터 보정과 JSON 선택

하단 **모터 영점 조절** 또는 **장치 연결 → 모터 영점 · 보정 파일**에서 사용합니다. 팔로워·리더와 USB를 먼저 선택합니다.

- **보정 파일 선택**: 기존 OpenCV·LeRobot·이 앱의 파일 목록에서 선택하거나 다른 JSON을 직접 고릅니다. 관절 6개의 영점과 최소·최대 틱을 확인할 수 있습니다.
- **파일만 등록**: 모터에는 쓰지 않고 이 앱의 로컬 사본을 선택합니다. 기존 연결을 해제한 상태에서 사용합니다. 다음 연결 때 모터의 현재 보정과 일치하는지 확인합니다.
- **선택한 파일을 모터에 적용**: 팔을 받쳤다는 확인 후 힘을 끄고 선택한 영점·범위를 모터에 저장하고 읽어서 확인합니다. 범위 측정을 다시 하지 않습니다.
- **새로 보정**: 파일 이름을 정하고 팔을 받친 뒤 시작합니다. 공식 그림처럼 관절·그리퍼를 중간에 맞춤 → 영점 기록 → 관절을 각각 양 끝까지 이동하고 그리퍼를 닫고 열기 → 범위 확인 → 모터와 파일에 저장 순서입니다. 손목 회전은 설치된 LeRobot의 공식 방식대로 0~4095 틱을 사용합니다.
- 이 절차는 `OpenCV_teach/motor_calibration.py`의 worker를 재사용합니다. 모터를 자동 이동시키는 목표·토크 ON 명령은 보내지 않습니다. 취소·창 닫기·화면 연결 끊김은 진행 중인 보정을 취소하고 이전값 복원을 시도합니다. 기존값과 복원 정보는 `outputs/motor_calibration/recovery_*.json`에 남습니다. 복원·해제 확인 실패는 오류로 표시합니다.
- 성공 후 선택한 팔의 로컬 보정 파일을 등록합니다. 등록 변경 전 설정과 기존 파일을 백업합니다. 다른 팔의 보정, 원본 OpenCV JSON, 기존 에피소드·모델은 덮어쓰지 않습니다. 좌표가 다른 과거 기록·모델의 실물 실행은 기존 호환 검사를 따릅니다.

기준: [LeRobot SO-101 공식 보정 절차](https://huggingface.co/docs/lerobot/main/en/so101#calibrate), 설치된 LeRobot 0.4.4의 `SO101Follower.calibrate()`와 `SO101Leader.calibrate()`. 별도의 소프트웨어 모델 자세 보정 기능은 제거했습니다. 시뮬 표시·리더 따라가기에는 공식 모터 보정값만 사용하며 추가 각도 오프셋을 더하지 않습니다.

## 온도와 모터 상태

SO-101 제어 프로세스는 최신 OpenCV 티칭의 활성화·건강 검사 함수를 재사용합니다. 기준은 `OpenCV_teach/settings.toml`입니다.

- 온도 raw 65 이상이 동작 중 5초 연속 유지되면 중단합니다. 관절·측정 경로별이며 정상 측정에서 해당 타이머만 초기화합니다.
- 시작 전 고온, 모터 상태 오류, 통신 오류, 잘못된 데이터는 즉시 알립니다. 고온 감시 중 1.5초 이상 측정이 없으면 중단합니다.
- 고온 지속 중에는 상단 알림을 사용합니다. raw를 검증된 섭씨·전압·토크 단위로 표시하지 않습니다.
- 기존 OMX의 12V/5V 분리 범위와 XL430/XL330 제어 레지스터는 SO-101에 쓰지 않습니다. 전압·온도 관련 모터 EEPROM 한계를 임의로 높이지 않습니다. 활성화 시 OpenCV와 동일한 LeRobot SO-101 설정을 사용합니다.
- 추가 고정 속도 필터는 기본 적용하지 않습니다. LeRobot 기본값처럼 상대 목표 한계는 사용하지 않으며, 공식 보정 범위와 진행 없는 정체 감시는 유지합니다.

전압의 별도 수치 임계값을 앱에서 판정하지는 않습니다. 현재 OpenCV와 동일하게 통신 패킷 오류·모터 `Status`·토크 상태를 검사하며, 모터 내부 전압 보호 설정을 바꾸지 않습니다. F8 정지는 힘을 유지하고, 명시적인 종료·모터 힘 끄기는 해제를 시도한 뒤 읽어서 확인합니다. USB 단절 등으로 확인하지 못하면 성공으로 표시하지 않습니다. 상세 점검은 [2026-09-22 안전 로직 확인](outputs/verification/so101_safe_pose_20260922/safety_review.md)을 참고하세요.

## 파일과 이전 OMX 기록

- 원본: `data/tasks/<작업 이름>/episodes/episode_000001/`
- 학습 파일: 같은 작업 폴더의 `lerobot` 링크. 오래된 `.lerobot_versions`는 필요한 학습 버전과 현재 링크를 보존하고 자동 정리합니다.
- 모델·학습 기록: `data/training/<작업 ID>/`
- 장비 등록: `config/robot.json`. 선택·생성한 보정 파일: `config/calibration/il_follower/<이름>.json`, `config/calibration/il_leader/<이름>.json`. 이전 `config/so101_leader.json` 등록도 계속 읽을 수 있습니다.
- 이전 OMX 설정: `config/legacy_omx/`. 기존 원본·모델을 SO-101로 변환하거나 삭제하지 않습니다. 이전 영상과 OMX 시뮬 재생·학습 기록 조회는 가능하며 SO-101 실물 실행은 차단합니다.
- 모델 생성: `scripts/prepare_so101.py`. 최신 티칭 모델과 두 카메라 마운트를 결합하며 원본 프로젝트를 수정하지 않습니다.

## 가벼운 자세 렌더러

- 기본 `./start.sh`는 `scripts/pose_view.py`를 별도 프로세스로 실행합니다. 기존 SO-101 URDF·교체 그리퍼·카메라 마운트·작업대와 과거 OMX 기록의 모델을 그대로 가져옵니다.
- 실제/저장 화면의 관절값을 받아 `mj_kinematics`와 `mj_camlight`로 위치만 계산합니다. 물리 시간 진행, 중력, 접촉 판정, 강화학습, 모터 명령은 없습니다. CAD 관절 범위 때문에 표시 각도를 잘라내지 않습니다.
- 최대 15fps, 960×640이며 자세가 같으면 다시 그리지 않습니다. 상태 알림은 계속 갱신해 정지 자세를 화면 오류로 표시하지 않습니다. 전송 파일은 `outputs/sim.jpg`, 상태는 `outputs/sim_status.json`, 오류 로그는 `outputs/sim.log`입니다.
- 렌더러 종료·영상 지연은 화면 알림으로 표시하고 오래된 이미지는 숨깁니다. 렌더러가 로봇 제어 명령을 보내거나 정지시키지 않습니다. 기존 USB·화면 heartbeat·모터 보호는 제어 프로세스에서 유지합니다.
- 기존 Isaac 화면이 필요한 경우에만 `./start.sh --renderer isaac` 또는 `./start.sh --sim-gui`를 사용합니다. 기본 실행에는 Isaac 환경이 필요하지 않습니다.

카메라 마운트 상세 도면·출력 STL·조립 기준은 [카메라 마운트 안내](assets/camera_mounts/README.md)를 참고하세요. 생성 순서: `scripts/build_camera_mounts.py` → `scripts/check_camera_mounts.py` → `scripts/prepare_so101.py`. 앞의 두 스크립트는 Isaac 환경의 Python을 사용하며, CAD 부울 연산은 이 폴더의 `.cad_runtime`에 별도 설치한 `manifold3d==3.5.3`을 사용합니다.


## SO-101 앱과 D435 컬러·깊이 (2026-09-22)

시스템 앱 메뉴·전용 창·웹 제목은 **SO-101 모방 학습**입니다. 메뉴 파일은 `~/.local/share/applications/so101-imitation-learning.desktop`, 배포용 원본은 `assets/so101-imitation-learning.desktop`입니다. 기존 OMX 메뉴 항목은 새 항목으로 바꿨으며 실행 명령은 그대로입니다.

```bash
final
cd Test_IL
./start.sh
```

- 새 녹화·학습·이어 학습은 SO-101용 작업 폴더와 모델을 사용합니다. 이전 OMX 기록과 모델은 조회·정리용으로 보존하며 실물 SO-101에 실행하지 않습니다. 기존 ‘미분류’ 폴더에 OMX 기록이 있으면 **폴더 관리**에서 새 SO-101 폴더를 만듭니다.
- 그리퍼: 32×32 UVC 모듈, MJPEG 640×480 / 30fps. 상단: D435, 컬러 BGR8와 깊이 Z16을 각각 640×480 / 30fps로 SDK에서 함께 수신합니다. D435는 USB 3 포트에 연결합니다. 장치 목록에는 SDK 일련번호를 표시하며 IR·깊이 V4L 장치를 컬러 카메라로 잘못 선택하지 않습니다.
- 상단 카메라의 **컬러 / 깊이** 버튼은 실시간·저장 기록 모두에서 동작합니다. 깊이 색상 범위는 표시용 0.1~1.5m, 빨강이 가깝고 파랑이 멀며 0(측정 없음)은 검정입니다. 이 범위 밖의 원래 거리도 파일에는 그대로 저장됩니다.
- 깊이는 컬러 픽셀에 정렬한 **uint16 무손실 PNG**입니다. 파일 위치는 `data/tasks/<작업>/episodes/episode_NNNNNN/table_depth/NNNNNNN.png`입니다. 새 RGB 기록은 `gripper/`, `table/`에 무손실 PNG로 저장합니다. 기존 JPG 기록은 그대로 읽습니다.
- `samples.jsonl`의 `cameras.table.depth`에 깊이 파일명·거리 단위·센서 시각·프레임 번호·유효 픽셀 비율을 저장합니다. 거리(m)는 픽셀값 × `scale_m_per_unit`입니다. 실제 장치가 보고한 단위를 사용하며 1mm라고 가정하지 않습니다.
- 에피소드 `metadata.json`의 `camera_streams`에 장치 모델·일련번호·카메라 내부 파라미터·깊이→컬러 변환을 저장합니다. 스무딩·구멍 채움은 하지 않습니다. 이 내부 파라미터와 로봇 기준 외부 보정은 별개입니다.
- D435 컬러 또는 깊이 수신이 끊겨 관측이 오래되면 기존 카메라 중단 알림으로 녹화를 중단하고 해당 녹화 저장을 막습니다. 수신 오류가 나도 깊이를 임의로 0으로 채우거나 RGB만 저장하지 않습니다. 과거 RGB 전용 기록은 ‘깊이 기록 없음’으로 표시합니다.
- LeRobot 변환·ACT 학습·모델 실행에는 `observation.images.wrist`, `observation.images.top`만 전달합니다. 깊이 원본은 별도 보관하며 학습 입력에 추가하지 않습니다.

SDK 정렬·거리 단위 기준: [RealSense 공식 Python 예제](https://github.com/realsenseai/librealsense/blob/master/wrappers/python/examples/align-depth2color.py).

검증: Python 205개, JavaScript 7개 통과. 합성 RGBD 기록 2개(16프레임)의 저장·변환, 작은 ACT 2-step 학습·체크포인트 저장·추론, 앱에서 모델 불러오기를 확인했습니다. 검증 자료는 `outputs/verification/so101_rgbd/`이며 실물 실행 불가로 표시됩니다. 현재 D435 미연결·리더 보정 미등록 상태이므로 실제 두 팔 녹화와 D435 수신 시험은 남아 있습니다.

## 2026-09-22 · 실행 호환성과 복구 수정

- SO-101 몸체의 ACT 출력은 도 단위 그대로 변환하며, ±100도로 임의 제한하지 않습니다. 해당 팔의 공식 보정 범위와 그리퍼 0~100% 범위는 유지합니다.
- 시작 직전 팔이 조금 움직이면 현재 자세를 다시 읽습니다. 이 경우를 USB 고장으로 고정하지 않습니다. 시작 이동의 완만한 보간은 유지하되 별도의 6° 도착 조건으로 대기하거나 중단하지 않습니다. 실제 위치 오차는 화면에서 확인하며 모터 오류·고온·진행 없는 정체 감시는 유지합니다.
- 자료 기본 방식과 시간 평균 방식은 추론 소요 시간만으로 오류를 내지 않습니다. 계산 중에는 마지막 목표를 유지하고 ‘추론 대기’로 표시합니다. 작업 시간 제한·사용자 정지·실제 추론 프로세스 오류·유효하지 않은 목표값 검사는 유지합니다. 미리 계산 방식의 시각 기반 동작 선택은 유지합니다.
- 자세 화면은 일시적인 서버 연결 실패를 최대 15초 동안 재시도합니다. 재연결 중에는 오래된 영상을 숨기고, 복구되면 같은 자세라도 화면 표시를 복원합니다. 모터에 명령을 보내는 기능은 없습니다.

이 앱에는 녹화 품질 검사, 공식 보정 일치 확인, 현재 자세에서의 시작 이동, 온도·정체·연결 끊김 대응이 있으므로 LeRobot CLI와 완전히 동일한 프로그램은 아닙니다. 실물 성공 여부를 시뮬 표시만으로 보증하지 않습니다.

## 2026-09-23 · LeRobot 기본 학습 방식 + D435

- 새 녹화의 `action`은 LeRobot 녹화 코드처럼 로봇 제한 전 리더 목표입니다. 실제로 전달한 값은 `command`에 별도로 보관합니다. 팔로워 목표는 공식 보정 범위로 제한하지만 임의의 상대 목표 30 제한은 추가하지 않습니다.
- 새 학습 방식은 메타데이터의 `learning_method=lerobot_native_rgbd_v1`로 구분합니다. 기존 에피소드와 모델은 재작성하거나 변환하지 않습니다. 새 방식의 비교 학습은 새 작업 폴더에서 시작하는 것을 권장합니다.
- 몸체 5관절은 도 단위, 그리퍼는 0~100%로 직접 LeRobot에 전달합니다. 데이터 변환 때 모터 틱을 다시 거치는 반올림은 제거했습니다.
- 카메라 원본 BGR 픽셀을 보존하고 녹화·추론에는 무손실 PNG를 사용합니다. JPEG는 웹 미리보기 전용입니다. UVC 모듈의 MJPEG 자체 압축을 복원하는 것은 아닙니다. 새 LeRobot 데이터셋의 영상 코덱은 원본 기본값인 libsvtav1이며, 기존 H.264 데이터셋에는 같은 코덱으로 추가합니다.
- 학습 데이터 로더·정규화·이어 학습 프로세서는 설치된 LeRobot 기본 경로를 사용합니다. 선택 에피소드 통계를 따로 재집계하거나 저장 정규화값을 강제로 덮어쓰는 앱 처리는 제거했습니다. 기본 ACT 구조·손실·옵티마이저는 그대로입니다.
- 제어·녹화 기본 주기는 30Hz, 자세 미리보기는 15fps입니다. ACT 기본 실행 방식은 LeRobot의 동작 큐를 사용하며 필터와 동작 연결은 기본으로 꺼져 있습니다. 모터 통신과 화면 정지를 계속 처리하기 위해 추론은 별도 프로세스에서 수행하므로 CLI와 실행 시점까지 완전히 동일하지는 않습니다.
- D435는 RGB와 컬러에 정렬한 uint16 깊이를 함께 저장합니다. 깊이 단위·센서 시각·내부 파라미터를 보존하고, ACT 학습 입력은 그리퍼 RGB와 D435 RGB 두 개입니다. 깊이를 ACT의 추가 채널로 사용하지 않습니다.
- 새 PC에서 ResNet18 사전학습을 켜면 LeRobot/torchvision의 기본 다운로드 경로를 사용합니다. 최초 실행에는 인터넷이 필요하며 데이터셋·모델을 Hub에 업로드하지 않습니다.
