## 계산 근거

- 본체 9개: `so101 부품들.gcode.3mf`의 객체 ID별 실제 G-code 압출량을 적분했습니다. E축의 상대·절대 모드, 리트랙션 회수, 원호를 처리하고 브림·스커트·서포트·사용자 시작 코드를 분리했습니다. G-code를 실행하거나 프린터에 전송하지 않았습니다.
- 본체 합계 255.529 g은 저장된 플레이트 예상값 255.54 g과 약 0.011 g 차이입니다. 합계를 강제로 일치시키도록 비례 보정하지 않았습니다.
- 출력물 이름의 숫자만으로 링크를 지정하지 않고, G-code 경로의 XYZ 범위를 조립 모델 메시 치수와 비교했습니다. 압출 중심선과 표면 사이의 차이를 포함해 최대 0.35 mm 이내인지 검사했습니다.
- TPU 손가락: 원본 `so101 tpu그립.3mf`를 같은 Bambu Studio 02.08.02.61로 다시 슬라이싱했습니다. TPU 95A HF, 밀도 1.22 g/cm³, Gyroid 15%, 벽 2겹, 레이어 0.2 mm를 유지했습니다. 동일한 손가락 4개는 합계 42.148 g이며 **1개당 10.537 g**, 현재 팔에는 2개를 반영합니다.
- 고정·가동 홀더: 본체 G-code 9개에 포함되지 않아 원본 XLeRobot 조립 메시의 출력 방향을 사용해 새로 슬라이싱했습니다. 사용자가 같은 출력 설정이라고 확인했습니다. PLA Matte, 밀도 1.32 g/cm³, Gyroid 15%, 벽 4겹, 레이어 0.1 mm, 노즐 0.2 mm를 적용했습니다. 고정 홀더 **23.178 g**, 가동 홀더 **6.478 g**입니다.
- 서보는 [FEETECH STS3215 제조사 사양서 4쪽](https://files.seeedstudio.com/products/Feetech/108090023_STS3215-C001_Datasheet.pdf)의 **55 ± 1 g/개**를 사용합니다. 현재 URDF의 서보 메시를 따라 베이스부터 고정 집게 측까지 각 1개, 총 6개를 배정했습니다. 가동 집게 링크에는 서보를 중복 추가하지 않았습니다.

## 고무 패드와 미산정 항목

사용자가 확인한 **Razer Universal Grip Tape**, 두께 **0.2 mm**를 `so101_contact.json`에 기록했습니다. Test_teach에는 폭 8 mm 팔각형 패드 2개, 정지 마찰 **1.0**, 운동 마찰 **0.8**, 반발 0, 마찰 결합 max를 시험용 추정값으로 적용했습니다. 면적·밀도·무게·마찰의 실측값은 없습니다. 표의 질량에는 패드·접착제, 별도 볼트·너트, 제어보드, 추가 배선, 테이블 클램프, 상단 카메라 마운트 무게를 더하지 않았습니다. 이 합계를 완성 로봇의 실측 총무게로 해석하지 않습니다.

## 파일과 검증

- `link_mass_estimate.json`: 링크별 g·kg 값, 부품 대응, 원본 해시, 미산정 항목.
- `pla_print_analysis.json`, `tpu_print_analysis.json`, `holder_print_analysis.json`: 부품별 압출량과 질량.
- `generated/`: 재슬라이싱 입력·출력 및 성공 결과. 원본 다운로드 파일은 수정하지 않았습니다.
- `gcode_mass.py`: 읽기 전용 압출량 분석기. 필라멘트가 하나인 슬라이스만 허용합니다.
- `build_report.py`: 보존한 근거 파일로 링크별 합계를 재생성합니다.

```bash
/path/to/venv/bin/python OpenCV_teach/calibration/link_mass/build_report.py
bash OpenCV_teach/run_tests.sh calibration.link_mass.test_gcode_mass
```

질량 합계만으로 새로운 질량중심과 관성 텐서가 결정되지는 않습니다. Test_teach의 계산은 각 구성 메시 내부를 균일한 질량 분포로 근사한 것이며, 근거는 `Test_teach/assets/so101/physics_provenance.json`에 기록했습니다. 원본 URDF와 모터 캘리브레이션은 유지했습니다.
