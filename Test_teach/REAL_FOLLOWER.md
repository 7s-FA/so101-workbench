# OMX 팔로워 실시간 연동

## 2026-09-17 Sim → Real 평가 모드

**Evaluation: keep speed below 6 deg lag**가 기본으로 선택됩니다. Enable 전에 체크를 해제하면 이전 자동 감속 모드로 돌아갑니다. 평가 모드는 팔 관절 오차가 6° 미만일 때 설정 속도(초기 경로 0.75배, 운반 경로 1배)를 유지하므로 작은 정적 오차로 시험이 계속 느려지는 현상을 줄입니다. 시작 자세 맞추기 속도는 기존 0.1 rad/s입니다.

6° 이상 또는 PWM 80% 이상이면 경로를 잠시 기다립니다. 평가 모드에서는 오차 5° 이하·PWM 70% 미만으로 회복하면 재개합니다(이전 자동 감속 모드는 3°). 약 10.3° 초과, 6초간 회복 진전 없음, 지속 과부하, 관절 범위·전압·온도·통신 보호 조건은 유지합니다. 시작 완료 조건도 안정된 상태에서 모든 관절 오차 3° 이내로 유지합니다. 이는 동작 재현 평가이며 정밀 파지 성공을 뜻하지 않습니다.

실제 Start로 시연이 진행 중인 표본만 `hardware_motion_error`에 집계합니다. 연결 종료 시 `outputs/follower/tracking_*.summary.json`에 관절 ID 11–16의 평균 절대 오차·최대 절대 오차·표본 수를 저장합니다. 대기·시작 정렬·Hold 시간은 제외하며, 경로 회복 대기 중의 오차는 포함합니다. 통계는 명령 각도와 보정된 엔코더 각도의 차이로, 외부 측정 TCP 오차가 아닙니다. 그리퍼(ID 16)는 물체 접촉으로 의도적인 각도 차이가 생길 수 있어 팔 관절과 구분해서 해석해야 합니다.

## 2026-09-17 가상 파지 안정화

하우징을 닫아 잡은 뒤 들어 올리는 중 `Physics became unstable`로 중단된 기록을 확인했습니다. 이 오류는 가상 관절 값이 유한하지 않거나 절댓값 7 rad를 넘을 때 발생합니다. 당시 보고서에는 발산한 관절·속도가 없어 정확한 최초 원인은 확정하지 못했습니다. 기울기 보정과 실물 모터 설정은 유지했습니다.

NVIDIA의 [mimic 접촉 안정성 설명](https://docs.omniverse.nvidia.com/kit/docs/omni_physics/107.3/dev_guide/rigid_bodies_articulations/articulations.html#articulation-mimic-joint-compliance)에 따라 가상 그리퍼의 완전 강체 기어 연결을 유한 강성·감쇠 연결로 바꿨습니다. `naturalFrequency=4000`, `dampingRatio=1.2`는 수치 안정화용 임시값이며 실물 기어 탄성의 실측값이 아닙니다. 마찰·접촉·기어 연동과 기존 실패 판정은 유지합니다. 발산 시 `report.json`의 `physics_failure`에 관절 이름, 직전 32개 표본의 목표·각도·속도·출력과 물체 상태를 남깁니다. `physics_metrics`에는 최대 손가락 연동 오차와 관절 속도를 기록합니다.

검증 결과는 `reports/physics_instability_20260917/`에 보관합니다. 사용자 실행에서 발생한 오류의 재발 방지를 보장하거나 실물 파지 성공을 검증한 것은 아닙니다. 실행 중인 앱에는 변경 사항을 즉시 주입하지 않습니다.

## 2026-09-17 링크 몸체 각도에 따른 1차 보정

`follower_visual_checked.json`의 어깨(ID 12)·팔꿈치(ID 13) 소프트웨어 영점을 갱신했습니다. 사용자가 측정한 **어깨 링크 몸체: 수직에서 뒤로 8°**, **앞팔 몸체: 손목 쪽으로 수평에서 아래로 8°**를 사용했습니다. URDF의 곧은 몸체 방향은 각각 link2의 +Z, link3의 +X이므로 관절각은 어깨 −8°, 팔꿈치 +16°입니다. 어깨와 팔꿈치의 관절 중심선은 몸체 방향과 다르므로 중심선 기준의 이전 후보는 사용하지 않습니다.

이는 한 자세에서 측정한 임시 보정입니다. 하중에 따른 처짐과 고정 영점 오차를 분리하거나 다른 자세에서 검증한 결과가 아니므로 `verified: false`를 유지합니다. 손목·베이스·그리퍼 기준과 모터 EEPROM은 변경하지 않았습니다. 이전 파일은 `reports/follower_before_link_body_calibration_20260917.json`에 보관했습니다.

현재 실행 중인 제어 프로세스는 기존 보정값을 유지합니다. 새 값은 다음 연결/실행부터 읽습니다. 앱 종료는 토크를 해제하므로 먼저 팔을 지지해야 합니다. 재연결 후에는 먼저 **Real -> Sim**에서 두 링크 방향을 대조하고, **Sim -> Real**에서는 새 각도 표시로 시작 자세를 맞춥니다. 이전 보정으로 학습한 자세 보정 맵은 파일 지문이 달라 재사용되지 않습니다.

시뮬레이션의 **관절 목표 각도**를 같은 PC의 OMX-F로 전달하는 선택 기능입니다. 아직 실물 보정·공차·파지·속도는 검증되지 않았습니다. 현재 시연은 모방학습 모델이 아니라 기존의 사전 구성 경로입니다.

## 같은 실행에서 버튼으로 모드 전환

```bash
final
./Test_teach/start.sh
```

**OMX modes**의 **Simulation only / Real -> Sim / Sim -> Real** 버튼으로 실행 중 전환합니다. 이전 시연과 USB 연결을 먼저 정리하고, 시연 모드는 가상 장면을 초기화한 뒤 정지 상태로 시작합니다. 전환만으로 실물 토크를 켜지 않습니다. `real.sh`는 같은 앱을 Sim -> Real 선택 상태로 여는 호환용 명령입니다.

2026-09-16 사용자가 실물 → 가상 자세 연동을 확인한 결과를 `config/follower_visual_checked.json`에 별도로 기록했습니다. 이 파일은 `verified: false`를 유지하며, **사용자 시각 대조 후 최초 저속 구동용**입니다. 정밀 보정 완료로 바꾼 것이 아닙니다. 실물 모드를 선택하면 측정 보정 파일 `follower.json`이 있으면 이를 우선하고, 없으면 이 별도 프로필을 명시적으로 허용합니다. 원래 후보 파일은 구동용으로 허용하지 않습니다.

1. **Sim -> Real**을 누르면 USB와 카메라를 연결하고 **읽기만** 합니다. `OMX real control`의 `Real deg / Start deg / Delta deg`로 현재·시작·차이 각도를 확인합니다.
2. 토크 OFF 상태에서 현재 팔을 지지합니다. 시작 각도에 손으로 맞출 필요는 없습니다. 실행이나 모드 선택만으로 팔을 펼치지 않습니다.
3. 그리퍼를 비우고 주변과 케이블의 여유를 확인한 뒤 **Enable follower**를 누릅니다. 현재 각도에서 준비 자세까지 0.5° 이하 간격으로 URDF·작업대·클램프·지그·초기 부품의 간섭과 관절 범위를 검사합니다. 충돌이 없으면 현재 엔코더 위치를 먼저 목표로 설정하고 토크를 켠 뒤, 최대 0.1 rad/s의 부드러운 동기 보간으로 이동합니다. 검사 후 실제 자세가 0.5°보다 많이 바뀌면 토크를 켜지 않고 새 각도로 최대 두 번 더 검사합니다. 계속 움직이면 연결을 유지한 채 팔을 지지하고 Enable을 다시 누르도록 안내합니다. 준비 동작은 화면에도 표시합니다. 도달 후 여섯 관절 오차 3° 이내·안정된 측정값·낮은 출력 조건으로 Ready가 됩니다. 초기 차이 10° 제한은 이 검사된 자동 진입 경로에 적용하지 않습니다. 실제 케이블·카메라 추가 형상·미등록 장애물·운반 중인 물체의 간섭을 보장하는 검사는 아닙니다.
4. `Ready`가 표시되면 **Start / Resume**로 시뮬레이션 경로를 실물에 전달합니다. 초기 팔 펼치기·그리퍼 열기는 0.75배, 부품 이송은 1배 시뮬레이션 시간으로 실행합니다. 경로에 맞춘 관절별 속도·가속도 프로파일을 사용합니다. 실제 속도는 통신·추종 상황에 따라 더 낮을 수 있습니다.
5. **Stop + hold**로 연결을 정지합니다. 지지 토크는 자동 해제하지 않습니다. 팔을 지지한 뒤 **Arm supported**를 체크하고 **Release motors**로 토크를 해제합니다. **Real -> Sim**으로 수동 관찰하거나, **Sim -> Real**을 다시 선택해 현재 자세에서 재활성화할 수 있습니다. 앱 재실행은 필요하지 않습니다.

실제 부품과 지그는 가상 배치에 자동으로 맞춰지지 않습니다. 실물 파지 성공 감지도 아직 없습니다. 먼저 물체가 없는 공간에서 동작을 확인하고, 물체 시험에는 실제 작업대·지그 위치 정합이 필요합니다.

기본 실행은 터미널의 Isaac 경고를 숨기고 Kit 로그에는 보존합니다. 실행 시 `ISAAC_LOG`로 파일 경로를 표시합니다. 오류와 실물 제어 중단 메시지는 계속 표시합니다. 경고도 다시 보려면 `./Test_teach/real.sh --show-warnings`를 사용합니다. 카메라 진단은 `reports/camera_stderr.log`에 기록하며, 카메라 프로세스 오류는 터미널에도 알립니다.

## 최초 연결

```bash
final
./Test_teach/hardware.sh devices
./Test_teach/hardware.sh inspect --port /dev/serial/by-id/실제_팔로워_USB이름
```

`devices`는 장치 목록만, `inspect`는 모터 설정·현재 위치·전압·온도·부하/전류를 읽습니다. 모터는 움직이지 않습니다. ID 11~13의 XL430-W250(1060), ID 14~16의 XL330-M288(1200)만 허용합니다. 리더 ID 1~6이나 다른 모터는 거부합니다.

OMX-F 공식 구성은 본체 12V 전원과 내부 DC 변환을 사용합니다. XL330 손목 모터 자체에 12V를 직접 넣는 구성은 아닙니다. 실제 제품의 전원 배선·정격을 유지하세요.

## 보정

```bash
./Test_teach/hardware.sh calibrate --port /dev/serial/by-id/실제_팔로워_USB이름
```

처음 보정은 손으로 팔을 지지한 토크 OFF 상태에서 합니다. **URDF 기준으로 실제 각도를 알고 있는 두 자세**를 입력하면 엔코더를 읽어 방향과 영점을 계산합니다. 각 관절은 두 자세에서 0.15rad 이상 달라야 합니다. 편한 자세를 임의로 0도로 입력하면 안 됩니다. 각도를 모르면 보정을 완료하지 말고 실물과 모델을 먼저 대조해야 합니다.

그리퍼도 닫힌 자세와 실제 각도를 측정한 열린 자세를 각각 읽습니다. 이 테스트는 최대 0.75rad까지 벌리므로 최소한 그 범위를 보정해야 합니다. 공식 모터 설정, 영점 EEPROM, ID는 자동 변경하지 않습니다. 성공하면 `config/follower.json`이 생성되며, 기존 파일은 덮어쓰지 않습니다.

리더 보정 파일은 사용하지 않습니다. 이 1차 연결기는 엔코더 한 회전 안의 동작만 지원하며, 0/4095 경계를 넘거나 모터 설정이 변경되면 다시 확인해야 합니다.

## 실행

```bash
final
./Test_teach/real.sh \
  --port /dev/serial/by-id/실제_팔로워_USB이름 \
  --camera /dev/v4l/by-id/실제_카메라-video-index0
```

카메라 없이 시험하려면 `--camera ...`를 생략합니다. 별도 카메라 창은 640×480 입력을 요청하고 최대 15fps로 표시합니다. 실제 제공되는 해상도·프레임률은 장치가 결정합니다. 영상에는 현재 시각이 표시되고 읽기 실패 시 창을 닫아 정지 화면을 실시간 영상으로 오인하지 않게 합니다. 인식·위치 보정은 수행하지 않습니다.

1. 프로그램은 시연을 시작하거나 모터 토크를 켜지 않습니다.
2. 현재 자세와 표시된 각도를 확인합니다. 시작 자세로 손으로 옮길 필요는 없습니다.
3. **Enable follower**에서 현재 자세에서 준비 자세까지의 간섭 검사 후 저속으로 자동 이동합니다. 검사된 자동 진입 경로에는 초기 ±10° 제한을 적용하지 않습니다. 모터 영점 설정을 변경하는 원점 보정과는 다릅니다.
4. **Start / Resume**를 누르면 두 팔이 같은 관절 목표를 따라 움직입니다. 초기 펼치기·열기는 0.75배, 집기·이송은 1배 시간으로 요청합니다. 경과 시간보다 앞서거나 지연 후 밀린 명령을 몰아서 보내지 않습니다.
5. **Pause / Reset / Stop follower** 또는 실물 제어 창 닫기는 실물 연동을 종료합니다. 다시 연결하려면 **Sim -> Real**을 선택합니다. 필요한 토크 해제와 시작 자세 확인 후에만 다시 활성화할 수 있습니다. Reset은 실물 팔을 초기 위치로 보내지 않습니다.

**Ctrl+C 또는 앱 창 종료**는 이 세션에서 활성화를 시도한 팔의 토크를 해제합니다. 종료 전에 팔과 물체를 지지하세요. **Stop + hold·모드 전환·통신 오류**는 지지 토크를 유지하며, 앱이 계속 열려 있으면 Release motors로 해제할 수 있습니다. 통신이 끊긴 상황에서는 소프트웨어 정지의 도달을 보장할 수 없고 모터의 300ms 버스 워치독을 사용합니다. 중력 낙하와 물체 낙하 방지를 위해 임의로 토크를 껐다 켜며 복구하지 않습니다.

GUI에서는 팔을 지지하고 **Arm supported → Release motors**를 사용합니다. 아래 터미널 명령을 사용할 때는 USB 포트 충돌을 막기 위해 앱을 종료한 뒤 실행합니다:

```bash
./Test_teach/hardware.sh release --port /dev/serial/by-id/실제_팔로워_USB이름
```

지지 확인 문자열을 입력하면 토크 OFF 후 워치독 오류를 해제합니다. 토크나 워치독 상태가 남아 있을 때 필요한 절차입니다. 보호 정지 후 자동 재개는 없습니다. 이 기능은 인증된 비상정지 장치의 대체물이 아닙니다.

## 제한과 검증 범위

- 실물 부품·출발/도착 지그·작업대 위치를 팔 베이스 기준으로 시뮬레이션과 맞춰야 합니다. 카메라 영상만으로 자동 정렬되지 않습니다.
- 실물 모드에서는 **가상 부품 위치를 이용한 내려놓기 보정은 사용하지 않습니다**. 가상의 파지 성공을 실제 파지 성공으로 표시하지 않습니다.
- 목표는 URDF rad 기준입니다. 관절별 허용 범위, 엔코더 범위, 실제 관절 오차 0.18rad, 신선도 0.2초를 검사합니다. 목표 변경이 `motion_timing.py`의 관절별 속도 제한(엔코더 양자화 여유 포함)을 넘으면 정지합니다.
- 기본 Evaluation은 작은 추종 오차에서 요청 속도를 유지합니다. 6° 이상 또는 팔 PWM 80% 이상에서 목표를 유지하고, 5° 이하·PWM 70% 미만에서 재개합니다. Adaptive는 2~6°에서 점진 감속하고 회복 재개 기준은 3°입니다. 6초 동안 0.25° 이상의 회복이 없으면 관절 ID와 원인을 표시하고 정지합니다. 그리퍼 접촉 오차는 공정 감속 판단에서 제외합니다.
- 모터 RAM 프로파일은 아래 “1배속 실물 재현 설정”의 관절별 속도·가속도로 설정합니다. 시간 기반 모드는 200ms/가속100ms를 유지합니다. 출력 설정은 아래 “OMX 제조사 기준 출력 설정”을 사용합니다. PID는 RAM에서 P=1000/I=0/D=1000, 그리퍼 목표 전류 상한은 600mA와 저장된 Current Limit 중 작은 값입니다. 운전 모드·영점·EEPROM은 변경하지 않습니다. 실제 파지력은 별도 검증 대상입니다.
- 팔 모드는 위치/확장 위치, 그리퍼는 전류 기반 위치 모드여야 합니다. 자동으로 모드를 바꾸지 않습니다.
- 전압·온도·하드웨어 오류와 SDK 통신 오류를 검사합니다. XL430 값은 부하(%), XL330 값은 전류(mA)로 구분합니다.
- 프로세스 종료 후 PID·PWM·속도 프로파일·목표 전류 RAM 값은 남을 수 있습니다. 의도적으로 이동 중 원래 고속 설정으로 복구하지 않습니다. 다른 제어 프로그램은 필요한 설정을 다시 적용해야 합니다.
- Isaac 렌더링이 길게 멈춰도 워치독이 동작하므로 고부하 환경에서는 연동이 중단될 수 있습니다. 통신 간격은 실제 장치 연결 후 측정해야 합니다.
- 자동 `--verify`, `--preview`, `--ui-smoke`, headless 실행은 실물을 구동할 수 없습니다.
- `Demo`·`Sim_real`은 수정하지 않았습니다. SDK는 기존 `Sim_real/.venv-io`의 Dynamixel SDK 3.8.4를 별도 프로세스에서 사용합니다.

## 자세별 실물 위치 보정 (2026-09-16)

현재 OMX의 위치 제어 모드에 맞춘 **측정 오차 기반 위치 오프셋 보정**입니다. 어깨·팔꿈치·손목 피치(ID 12~14)에만 적용하며, 역동역학의 중력 토크 g(q)를 모터에 직접 보내는 방식은 아닙니다. XL430을 포함한 이 구성에서 운전 모드나 전류·PID를 자동으로 바꾸지 않습니다. 엔코더에 나타나는 정적 처짐/잔류 오차를 줄이는 목적이며, 링크 휨·백래시·카메라 외부 보정·작업대 위치 오차는 별도 측정이 필요합니다.

- 총 위치 보정 ±3°, 변화율 최대 0.5°/s. 관절/엔코더 한계에서 가능한 값으로 추가 축소합니다. 이때 범위를 지키기 위한 축소가 변화율 제한보다 우선합니다. 이 위치 보정은 자동 진입 절차나 기존 보호 정지 조건을 대체하지 않습니다.

- `free` 구간에서만 정지 표본을 학습합니다. 내려가기·닫기·들어 올리기·내려놓기·열기는 `contact` 구간으로 분류해 학습/저장값 적용을 중지하고 기존 보정량을 서서히 줄입니다. 정렬 말기에는 피드백만 허용하며 지도 학습은 하지 않습니다. 통신 지연이나 불완전한 표본은 학습하지 않습니다.

사용 순서:

1. 기존과 같이 `final` 후 `./Test_teach/start.sh`, **Sim -> Real**을 선택합니다. **Control details → Position compensation**은 기본 ON입니다. OFF 상태에서 Enable하면 동일한 보호/속도 로직으로 보정 전후를 비교할 수 있습니다. 활성화 동안 옵션은 잠깁니다.

1. 실제 저장된 모든 PWM Limit과 그리퍼 Current Limit을 읽고 유효성을 검사합니다.
2. 현재 엔코더 위치를 목표로 설정한 다음, 토크 OFF 상태에서 ID 11~16의 P/I/D를 1000/0/1000으로 설정합니다.
3. Goal PWM은 각 모터의 저장된 PWM Limit까지 허용합니다. 그리퍼 Goal Current는 `min(600mA, Current Limit)`입니다. 600mA를 지속해서 흘리거나 모터의 하드웨어 한도를 늘리는 설정은 아닙니다.
4. 설정을 모두 다시 읽어 일치하는 경우에만 토크를 켭니다. 불일치·통신 오류이면 토크를 켜지 않습니다. 활성화된 설정은 추종 로그의 `power_profile`에 남습니다.
5. 게인·출력 상한이 달라진 경우 기존 경험적 자세 보정 맵은 재사용하지 않습니다.

근거: [ROBOTIS OMX 팔로워 설정](https://github.com/ROBOTIS-GIT/open_manipulator/blob/main/open_manipulator_description/ros2_control/omx_f.ros2_control.xacro), [XL330 Goal Current](https://emanual.robotis.com/docs/en/dxl/x/xl330-m288/#goal-current102).
제조사의 RAM 게인·그리퍼 전류 값을 참고하되, 현재 제어기의 관절별 속도/가속도, 운전 모드와 보정 기준을 유지합니다. 제조사 ROS 컨트롤러 전체와 같은 구성이라는 의미는 아닙니다.

현재 실행 중인 앱/지지 중인 모터에는 이 변경을 즉시 쓰지 않았습니다. 앱 재시작 후 Enable에서 적용합니다. 재시작을 위해 종료할 때에는 먼저 팔을 지지합니다. 이번 출력 변경은 가상 버스 검사까지 완료했으며, 변경된 게인에서의 실물 진동·추종 오차·파지 성공은 재시험 대상입니다. 출력 상한과 제어 게인의 변경만으로 사진에서 보이는 구조 변형·기어 유격까지 제거되지는 않습니다.


## 2026-09-17: Ctrl+C / 창 닫기 종료 처리

`start.sh`(또는 이를 사용하는 `real.sh`)가 Isaac 외부의 실행 관리 프로세스를 시작합니다. 모터 통신이나 그래픽 드라이버 호출에서 Isaac의 Python 처리가 지연돼도 실행 관리 프로세스는 Ctrl+C를 받습니다.

- Ctrl+C 1회: Isaac에 종료를 전달하고 정상 정리를 최대 4초 기다립니다.
- Ctrl+C 2회: 남은 정상 정리 대기를 줄입니다. 모터 토크 해제 확인은 생략하지 않습니다.
- 창의 X 버튼: 창 닫기 이벤트가 발생할 때 실행 관리 프로세스에 즉시 알립니다. 이벤트를 처리하지 못할 정도로 GUI가 멈췄다면 터미널 Ctrl+C를 사용합니다.
- 정리 시간 초과: 이번 실행이 만든 전용 프로세스 그룹(Isaac, USB worker, 카메라)만 종료합니다. 다른 Isaac·프로젝트 프로세스를 이름으로 검색해 종료하지 않습니다.
- 명시적 종료이고 이 실행에서 모터 활성화를 요청한 포트가 있다면, 정상 정리의 토크 OFF 확인 여부를 검사합니다. 확인되지 않았으면 USB 소유 프로세스를 종료한 다음 기존 장치 검사·토크 OFF·읽기 확인 명령을 별도 프로세스에서 실행합니다(최대 5초).
- USB 단절이나 다른 프로그램의 장치 점유 등으로 해제를 확인하지 못하면 `EXIT TORQUE OFF NOT CONFIRMED`를 표시하고 실패 코드로 종료합니다. 이 경우 팔을 지지하고 `./Test_teach/torque_off.sh`로 다시 확인해야 합니다.
- 예기치 않은 오류 종료는 기존대로 지지 토크를 유지합니다. 의도적인 Ctrl+C/창 닫기와 구분합니다. Simulation only나 읽기만 한 실행은 종료 시 모터에 쓰지 않습니다.

IsaacLab의 STOP 콜백이 재생 재개까지 렌더링을 반복하던 경로는 이 앱에서 비활성화했습니다. 이미 실행 중인 앱에는 이 수정이 소급 적용되지 않습니다. 종료 시에는 기존과 같이 팔과 물체를 지지하세요.

검증: 실제 USB를 열지 않는 별도 프로세스 테스트로 Ctrl+C, 재차 Ctrl+C, 창 닫기 콜백, 신호를 무시하는 프로세스, 남은 카메라 자식 정리, 다른 앱 보존, 토크 해제 확인 실패, 예기치 않은 오류에서 토크 유지 정책을 확인했습니다. 현재 사용자가 실행 중인 Isaac 창을 강제로 닫거나 실물 토크를 해제하는 시험은 하지 않았습니다.


## 마지막 복귀 자세

시연 끝은 기존 작업 높이의 Park 자세 대신 `config/scene.json`의 `start_angles_deg`와 같은 자세로 복귀합니다. 부품을 내려놓고 후퇴 → 작업 높이 경유 → 시작 자세 복귀 → 1초 유지 순서입니다. 손목 회전과 그리퍼 벌림도 초기값으로 맞춥니다. 복귀 구간은 시작 전개와 같은 최대 관절 변화율 기준으로 시간을 계산하고 실물 배율 0.75를 사용합니다.

`scripts/audit_return_pose.py`는 실제 시연 단계 생성 코드를 사용해 일반/실물 계획 모드 × 전체/하우징/볼/덮개 8개 경우를 검사합니다. 결과는 `reports/return_to_start_audit.json`에 저장됩니다. 복귀 목표 일치, 엔코더/관절 범위, 속도/가속도와 복귀 중 명목 메시 간섭을 검사하며, 부품은 도착 위치로 옮기고 출발·도착 지그는 유지합니다. 실물 잔여 추종 오차와 케이블 간섭까지 보장하는 검사는 아닙니다.
